# 个人经历库（通用空白模板）

> 用途：通过自然语言持续记录个人经历，由AI追问并整理成可检索、可追溯的经历档案；再配合目标岗位JD和既有简历模板生成针对性简历。
>
> 核心原则：用户负责讲述和确认事实，AI负责追问、整理、索引和匹配。用户不需要手工拆解STAR，也不需要重复维护能力与成果索引。

## 0.1 状态标签

本文件使用两类状态，含义不同，不可混用。

### 信息确认状态

- `用户已确认`：用户明确确认内容准确，可以作为正式简历的事实来源。
- `资料来源-待本人复核`：内容来自旧简历、证书、作品或其他资料，需要本人确认。
- `AI整理-待确认`：AI根据用户叙述整理，必须经用户确认。
- `待补充`：缺少会影响简历真实性或核心表达的必要信息，AI通过追问解决。
- `可选待补充`：信息可能增强表达，但不影响当前经历入库或简历草稿，默认不追问。
- `存在冲突`：不同来源说法不一致，未澄清前不得选用。

### 能力状态

- `用户自述`：用户直接说明掌握或使用某项技能，不强制绑定项目；可按真实范围用于简历技能栏。
- `已验证`：能够关联到具体经历、作品、结果、数据或验证过程。
- `可迁移`：能够从已有经历合理推导，但尚未在目标场景直接验证。
- `待补齐`：当前材料不足以证明，应先学习、练习或完成验证任务。

# 第一部分：AI采集与维护规则

## 1.1 自由讲述采集流程

用户可以直接用自然语言讲述经历，不要求按照固定格式。例如：

> 我在一个项目中负责数据分析。最初结果波动很大，我检查了数据来源和处理流程，后来重新设计了清洗规则，并做了自动化脚本，最终把处理时间从两天缩短到半天。

AI收到叙述后，应按以下顺序处理：

1. 每个任务只定位一次经历库，并在当前任务中记住路径。
2. 将用户原话或忠实转述保留为“来源叙述”，先识别已提供事实，不得重复询问。
3. 分别判断“可入库”和“简历充分”：能识别独立经历并忠实保存即为可入库；只有具备具体个人行动、对象、结果／交付及必要限定词时才为简历充分。
4. 用户明确要求加入、记录或保存时，对可入库材料立即一次性写入；简历不充分的记录标记原因，不生成候选简历表述。
5. 当前任务需要简历级表述而又缺少必要信息时，一次性提出一至三个相互关联的关键补充项；这一轮只提问，不读取整库、不写文件。
6. 用户回答后直接整理可用内容，不继续逐项追问；只有用户明确启用“精细模式”才逐轮深入。
7. 每次提交一次性写入来源、主记录、简历充分性和直接相关索引，AI改写标记为`AI整理-待确认`；每段经历或每批内容最多追加一条维护日志。
8. 全库索引重建延迟到采集结束、分析JD或生成简历之前。

## 1.2 AI追问决策门槛

追问不是必选步骤。只有当前任务需要达到简历充分性时，每个问题才必须同时满足：

1. 信息确实没有提供，或现有材料存在明确且实质性的冲突。
2. 答案会改变简历核心事实、个人贡献边界、经历取舍、JD匹配或候选表述。
3. 用户能够凭记忆简短回答，不需要查论文、翻记录、计算或重建全过程。
4. 无法通过保留限定词、中性措辞或省略非关键细节安全处理。
5. 预期简历价值明显高于用户回答成本。

任一条件不满足，就不提问。可以将有帮助但不必要的信息标记为`可选待补充`，不得阻塞入库。对于用户明确要求保存的可入库材料，先完成保存；简历充分性不足只能影响候选表述，不能把该轮改成不写文件的澄清轮。

问题通过门槛后，依次优先考虑：个人贡献边界、关键行动、对目标岗位有意义的结果或交付、JD明确要求的工具或条件。

默认“极速采集”每段经历最多发出一轮补充请求，一轮可包含一至三个相互关联的必要项。每个补充项都必须独立通过上述门槛。提问轮只输出简短问题，不展示完整经历草稿或字段表。

当已有事实能够形成至少一条准确、岗位相关且包含具体个人行动的候选表述时，停止追问并直接整理。量化指标不是必需项，但“参与某项目、效果不错”不能作为充分信息；此时优先追问本人具体做了什么。不要转而询问公司名称、精确时间、技术细节或证明材料，也不要为了填满字段、维持对话或让档案显得完整而继续提问。

默认属于“简历采集”，不做论文复现、技术审计或项目取证。文献编号、完整组成清单、全部参数与边界条件、完整公式、设备序列号、每个渠道或每位协作者等细节，只有在目标JD会直接使用该信息，或用户明确要求深度复盘时才处理。

## 1.3 信息维护规则

- “来源叙述”是唯一事实底稿，AI不得静默覆盖或改变原意。
- 当前消息中已明确提供的职责、行动、工具、数据和结果均视为已知信息，不得重复询问。
- 相同事实只建立一份主记录，其他章节通过经历ID引用。
- 经历库路径在同一任务中只查找一次；后续按经历ID或标题局部读取，不重复扫描整库。
- 询问阶段只在对话中暂存，禁止每轮写入文件。
- 能力索引和成果索引由AI派生；单段采集只更新直接受影响的条目，全库重建延迟到采集结束、JD分析或简历生成前。
- 技能索引、能力缺口和旧版“本轮唯一问题”不是自动提问队列，不得为了给技能绑定项目而追问。
- 用户直接说明掌握某项技能时标记为`用户自述`；没有自然项目证据也不询问“在哪个项目使用过”。
- 维护日志按完成的经历或批次记录，不按每次回答记录。
- 只有阻塞安全表述的缺口标记为`待补充`；非关键增强项标记为`可选待补充`或直接省略。
- 不得仅因数据、方法或结果看起来少见而质疑用户。只有同一事项存在互斥陈述、标签或单位使含义无法确定，或用户明确表示不确定时，才判断为冲突。
- 动态信息如年龄、在读状态和“至今”应在每次生成简历时复核。
- “参与、协助、预计、规划、申请中”等限定词不得被删除。
- 涉及商业机密、个人隐私或保密项目时，先确定可公开边界再生成简历。

## 1.4 允许的优化

- 将口语叙述改写为清晰、专业、符合JD语言习惯的表达。
- 在不改变事实的前提下补充公认的上位概念、同义词和行业关键词。
- 从已验证经历中推导可迁移能力，并标记为`可迁移`。
- 针对`待补齐`能力设计学习路径、练习任务、小型作品和面试自测题。
- 用户完成验证任务并提供结果后，将能力升级为`可迁移`或`已验证`。

## 1.5 禁止的扩写

- 不得编造公司、岗位、时间、项目、客户、论文、专利、证书或奖项。
- 不得把团队成果改写为个人独立成果。
- 不得把“参与、协助、规划、预计、申请中”改写为“主导、完成、已实现、已授权”。
- 不得编造数量、比例、金额、性能或效率等量化结果。
- 不得仅因JD出现某项技能，就将其写成候选人已经掌握。

## 1.6 用户常用指令

- “我要新增一段经历，必要信息请一次问完，最后只写入一次。”
- “检查所有`待补充`和`存在冲突`内容，按价值从高到低逐项问我。”
- “分析这份JD，先输出匹配报告和能力缺口，不要马上写简历。”
- “根据这份JD和指定简历模板生成一页简历，所有关键表述必须关联经历ID。”
- “为待补齐能力制定最短验证任务，完成后再判断能否进入简历。”

# 第六部分：JD匹配与简历生成规则

## 6.1 必要输入

每次生成定制简历时，至少需要：

1. 本经历库。
2. 完整目标岗位JD。
3. 指定简历模板，或模板栏目、页数和语言要求。

如缺少JD或简历模板要求，AI应先说明缺失内容，不直接声称已生成“定制简历”。

## 6.2 JD拆解

AI先提取：

- 岗位核心目标。
- 必须满足的硬条件。
- 高频职责和业务场景。
- 软件、方法、行业知识和行为能力关键词。
- 加分项。
- 隐性要求，如验证意识、跨部门协作、工程落地或自动化能力。

## 6.3 匹配报告

写简历前，先输出：

| JD要求 | 匹配状态 | 经历／能力ID | 证据 | 处理建议 |
|---|---|---|---|---|
| `[要求]` | `[强匹配／中匹配／弱匹配／缺口]` | `[ID]` | `[项目、结果或证明]` | `[重点写／辅助写／先补齐／不写]` |

判断标准：

- **强匹配**：存在直接、已验证且场景相近的经历。
- **中匹配**：能力已验证，但行业或场景不同，需要合理迁移。
- **弱匹配**：只有课程、理论认知或间接经验。
- **缺口**：没有可信事实或验证任务支撑。

## 6.4 能力快速补齐

对于`待补齐`能力，AI先给出最短可验证路径：

1. 明确学习目标和完成标准。
2. 推荐最少必要资料。
3. 设计一个与目标岗位接近的小型练习、案例或作品。
4. 规定需要保留的证据，如代码、模型、报告、计算文件或演示结果。
5. 提供三至五个面试自测问题。
6. 用户完成并提交结果后，再判断能否升级为`可迁移`或`已验证`。

能力升级时，必须新增验证记录并注明完成时间和证据，不能只修改标签。

## 6.5 简历内容选择

- 优先选择与JD核心目标最相关、证据最强的三至五段经历。
- 每段经历优先使用“问题／目标—个人行动—结果／验证”结构。
- 同一结果只出现一次，避免在概述、技能和项目中重复堆砌。
- 数字必须连同比较基准、工况和限定词一起使用。
- 对“申请中、预计、规划、参与、协助”等状态保持原意。
- 一页简历只保留最能影响招聘判断的信息，无关内容可以省略但不从经历库删除。
- 可以使用JD中的同义关键词，但不得为了关键词命中而虚构技能。

## 6.6 映射到指定简历模板

AI先识别用户提供的模板栏目、容量、页数和语言，再把经历库内容映射到对应位置。常见映射如下：

| 简历栏目 | 经历库来源 |
|---|---|
| 抬头与求职方向 | 第二部分基本档案＋目标JD |
| 个人／专业概述 | JD核心目标＋最强的两至三项能力与成果 |
| 教育背景 | EDU记录 |
| 技术／专业能力 | 技能索引中与JD直接相关、且状态允许使用的项目 |
| 工作／实习经历 | WORK、EXP记录及对应量化成果 |
| 项目／科研经历 | 与JD相关度最高的PROJ、RES记录 |
| 作品／论文／专利 | PORT记录 |
| 荣誉与证书 | ACH记录，按岗位相关性和版面选择 |

## 6.7 输出前自检

- 每条关键表述是否关联至少一个经历ID？
- 是否把团队成果错误写成个人成果？
- 是否删除了“预计、申请中、约、参与”等必要限定词？
- 所有数字是否与经历库一致，并带有必要工况和比较基准？
- 是否使用了`存在冲突`或尚未验证的`待补齐`内容？
- 是否符合模板页数、栏目和语言要求？
- 是否有与JD无关的内容挤占关键经历版面？

## 6.8 建议输出顺序

1. JD结构化拆解。
2. 经历匹配报告。
3. 能力缺口与最短补齐方案。
4. 本次选用／省略的经历ID及理由。
5. 按指定模板生成的定制简历内容。
6. 事实追溯与风险检查结果。
