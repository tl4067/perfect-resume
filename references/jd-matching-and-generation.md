# JD matching and resume editing

1. Requirement record

## Requirement record

Before drafting, extract each requirement into a row with:

- requirement text or faithful summary;
- source type: 明文要求或分析推断;
- nature: hard condition, core responsibility, tool or method, domain context, behavioral expectation, or bonus item;
- evidence IDs and evidence scope;
- status: 已满足, 部分满足, 未知, or 明确不满足.

Do not promote a repeated keyword to a hard condition when the JD gives no priority. Keep 优先, 加分, and 有经验者佳 as non-mandatory bonus language. An inferred requirement must remain labeled as an inference.

## Matching dimensions and report

Judge these internally and separately:

| Dimension | What to inspect |
|---|---|
| Source | Self-report, concrete experience, or supplied material awaiting review |
| Relevance | Same context, defensible adjacent context, or no clear link |
| Depth | Exposure, independent execution, design, or decision responsibility; unknown stays unknown |
| Recency | Whether the evidence still relates to the role; old evidence does not expire automatically |
| Status | 已满足, 部分满足, 未知, or 明确不满足 |

Strong, medium, and weak may be used as a compact summary, but never replace the dimensions above or become an unsupported percentage.

Show a report before drafting a targeted resume. This is an output-order rule, not a waiting or approval gate when the user already requested generation.

| JD requirement | Nature | Status | Source IDs | Evidence and boundary | Resume action |
|---|---|---|---|---|---|
| Requirement text | Core or hard/bonus label | One status above | IDs or none | Concrete fact, scope, and limitation | Emphasize, support, clarify, report gap, or omit |

Unknown means the supplied material does not mention the requirement; it does not mean the user lacks it. Clearly unmet means the user has supplied a fact that contradicts the requirement. Separate adjacent evidence from direct evidence.

## Gap routing

JD analysis defaults to a gap report: gap type, effect on fit, and a suggested next handling. Do not automatically expand a learning plan.

Create a plan only when the user explicitly asks to learn, fill, or strengthen the gap. For a plan, specify:

1. minimum learning or practice objective;
2. a small task resembling the target context;
3. completion criteria;
4. evidence to save;
5. interview self-check questions.

Classify gaps before choosing the response:

| Gap type | Default handling | If the user asks to fill it |
|---|---|---|
| Information not provided | Mark 未知; ask one critical question only if needed | Gather the fact; do not assume a course is needed |
| Tool or method practice | Report insufficient evidence | Design a task and save its output |
| Scene or industry experience | State transfer boundary | Simulated case may be used but remains labeled simulated |
| Work years or management scale | Report the difference | Never claim a short task replaces years or scale |
| Degree or formal credential | Report supplied status | Use official requirements if needed; no practice substitute |

完成的练习可以支持所描述的个人项目或练习能力，但不能变成公司工作、生产环境部署、正式工作年限、学历、资质或管理经验。

## Content selection and bullet editing

Choose content in this order:

1. facts that best support hard conditions and core responsibilities;
2. concrete personal actions and results or deliverables;
3. high-information evidence when multiple records prove the same capability;
4. space allocation based on the user's page, language, and material density;
5. omit irrelevant content from the resume without deleting it from the library.

三至五段经历只是参考范围，不是配额。关键记录即使使简历变长也应保留；用户明确要求两页资深简历时按两页组织。默认一页只是版式偏好，不是编造内容或缩小字号的理由。

Each bullet should focus on one main action or result. Across an experience, cover the goal or problem, personal action, and result or deliverable when supported; an individual sentence need not contain all of them. Use a metric when it carries information, but a concrete qualitative output is enough.

Review each bullet in this order:

1. facts and qualifiers;
2. what the person did;
3. visible relation to the role;
4. tools serving the action rather than a list;
5. result versus impact and the evidence for causality;
6. duplicate, vague, or unnecessary background;
7. readability at normal size.

Allowed transformation: concise rewriting, ordering, synonym normalization, and evidence-backed keyword alignment. Example:

Input: 我负责数据清洗，写了自动化脚本，把处理时间从两天缩短到半天。
Allowed: 负责数据清洗并编写自动化脚本，将处理时间由两天缩短至半天。
Do not add a programming language, user count, revenue, or leadership claim that was not supplied.

## Assembly and final audit

Use the smallest evidence set that explains fit. A self-reported skill may appear in the skills section with its stated scope even without a project link. Unsupported project keywords stay out.

For each material claim, keep an internal source ID mapping. Before delivery reject or revise a sentence when it:

- cannot be traced to a source ID;
- adds a routine technical step, tool, domain, or scale absent from the source;
- changes participation level;
- turns an estimate, plan, application, or ongoing task into a completed result;
- drops the baseline, operating condition, range, or uncertainty needed to interpret a number;
- uses personal data not approved for this resume.

For a local edit, change only the requested passage and evidence-supported surrounding text. For a review, report issues without editing by default. For a complete academic CV request, explain that a job-resume one-page assembly is outside this dedicated scope and process only explicitly requested components.
