## Template location

Use `assets/resume-template-ats.docx` only when the user did not supply a resume template. Copy it to the user's workspace before editing; never overwrite the asset.

## Placeholder map

The built-in template retains the visual style of the source resume and uses visible bracketed placeholders for:

- Name, role keywords, profile facts, phone, email, and target role
- Professional summary
- Two education entries and relevant courses
- Software or domain skills and methods or theory
- One work or internship entry
- Three project entries
- Awards and qualifications

Replace placeholders with evidence-backed content. Remove unused rows, bullets, and sections rather than leaving placeholders in the delivered resume.

## Adaptation rules

- Preserve fonts, color, margins, spacing, rules, and hierarchy.
- Reorder or hide sections when the JD makes another order more persuasive.
- Keep the final page count requested by the user; default to one page for the built-in template.
- Prefer fewer strong entries over compressed, unreadable content.
- If content does not fit, remove lower-value material before reducing body text below a readable size.

## Page balance for one-page resumes

For a default one-page A4 resume, aim for a visually balanced page that is close to full while retaining normal, readable typography and useful white space. Use this order:

1. Add only JD-relevant, evidence-backed content already available: another strong project or experience, supported skill, relevant course, award, qualification, or work sample.
2. Where the evidence supports it, express existing experiences as concise personal-action-and-result bullets instead of thin labels.
3. Reorder sections and use the template's existing spacing to balance the page.
4. If the evidence is still limited, keep clean whitespace and state the evidence limitation if useful.

Do not fill space with generic self-evaluation, unrelated history, invented specifics, duplicate bullets, stretched paragraphs, or text reduced below a readable size.

## Privacy and rendering checks

Inspect body text, tables, headers, footers, comments, tracked changes, hyperlinks, image alternative text, custom XML, and document properties. Confirm that no source person's name, contact data, institutions, employers, projects, awards, metrics, authors, or last-saved-by metadata remain.

Render the final DOCX and visually inspect every page for overflow, overlap, clipped text, empty headings, broken alignment, and avoidable large blank areas. For a sparse but truthful one-page resume, reasonable white space is acceptable.
